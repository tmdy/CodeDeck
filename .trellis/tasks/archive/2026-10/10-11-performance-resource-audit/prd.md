# CodeDeck 性能基线审计与低风险资源优化

## 目标与本轮范围

完成 Windows CodeDeck 第一阶段性能审计：核实现有进程、资源所有权和数据流，建立可复现基线，按收益与风险排序，并实现有证据的低风险、高收益修复。用户已明确授权本轮审计、测量、修复及创建任务；不额外引入审批环节。

## 已确认背景

- 基线为 2026-10-11 当前工作树，HEAD `8ec9190`，进入任务时已有 62 项未提交变更；保留这些变更，尤其是 10-10 监控身份、回合完成和自动继续修复。
- 正在运行的是 `release/codex-resume-repair-20261010/win-unpacked/CodeDeck.exe`，不把该进程数据当作当前源码的前后对照。
- 当前为 Electron 39 / React 19 / TypeScript，受监控终端各自拥有 BrowserWindow；实际 Provider 支持以注册实现为准。
- `terminal-session-manager.ts:284-297` 关闭后未移除 sessions 条目；`:421-428` 每个输出块重建最多 64,000 字符历史；`:223` 每块通知完整状态。
- `TerminalApp.tsx:185-190,285-301` 每个状态更新触发 React 和 fit/resize；`session-list-cache.ts:95-136` 过期条目仅在同 key 再访问时移除，缺少总容量边界。
- `session-service.ts:1009-1066` 已有 stat 缓存和追加读取；旧版“每两秒全读索引”不能直接套用当前代码。

## 需求

- **R1 审计**：涵盖 Main/Renderer/Preload、后台服务/托盘、Provider 生命周期、PTY、会话索引、缓存/持久化、定时器/监听/网络、模型目录。列出创建者、持有者、销毁者及仍需后续验证的热点。
- **R2 基线**：覆盖启动/空闲/隐藏、单个与多个受监控终端、持续输出、创建切换关闭、已退出历史窗口、连续关闭、空闲恢复。分别标明真实进程、隔离 Electron、合成负载和未测指标，区分应用与 CLI 工作集、私有提交、CPU、I/O、资源数量及耗时。
- **R3 低风险修复**：优先消除关闭资源保留、重复历史拼接/传输、输出导致的无效布局工作和可重载缓存无限增长。保留既有 64,000 字符重连窗口、原始输出流、ANSI/Unicode 顺序和退出窗口中的可见历史。
- **R4 行为与数据**：保留现有 Provider 配置/启动/系统终端/恢复/自动继续/权威状态；不修改真实 API Key、模型设置、工作目录和历史，不向真实 CLI 会话输入探测内容，不消耗模型 Token。
- **R5 验证**：产出可复用测试与测量脚本，修复前后同口径比较。明确 OS 测量与逻辑保留量的差别，不把 GC 后堆大小、测试通过或源码构建当作实机功能证明。

## 本轮不做

大规模架构替换、新框架、强制 GC/周期性清内存/重启、改 CLI 本身、重写真实索引、清理真实数据、发布安装包或 Git 提交推送。事件驱动监控、完整历史分级持久化和模型 fallback 策略作为排序后的后续事项，除非本轮证据支持安全的小修复。
